## 4. Вывод по скриншотам

Диалог Android, предлагающий открыть «小米运动健康», означает, что система нашла цель перехода и запрашивает подтверждение. Он не доказывает прохождение дальнейшего согласования разрешений, чтения данных или фоновой синхронизации. Эти этапы проверяются отдельным функциональным тестом на телефоне.

## 5. Правило для следующей русификации

1. Оригинальный `com.mi.healthresearch` APK не заменять, не пересобирать и не переподписывать.
2. Никакие классы `com.mi.fitness`, `com.xiaomi.fitness`, `com.xiaomi.fit.fitness.sync.export`, `com.mi.hospital.sync`, сервисы, экспортируемые Activity, разрешения, intent actions и `.so` не патчить.
3. Для внешней локализации ограничить LSPosed scope только `com.mi.healthresearch`.
4. Hook-и ограничить установкой видимого текста (`TextView.setText`) и строгим scope `com.mi.healthresearch`. Не перехватывать WebView/URL, Intent, Binder, Service, PackageManager или методы синхронизации данных: поддержка русской локали на сервере Xiaomi не подтверждена, поэтому изменять URL рискованно.
5. Динамический текст переводить только при точном совпадении исходной строки, чтобы не менять значения данных, идентификаторы, маршруты и ответы API.
6. До признания результата готовым отдельно проверить на устройстве: открытие Mi Fitness, авторизацию/разрешения, чтение данных, вступление в исследование и обратный переход. Сборка CI сама по себе не подтверждает этот тест.

## 6. Сопоставление результатов независимых проверок

- **Бинарное сравнение APK:** проверило подпись, структуру манифеста, DEX, архивные ресурсы и нативные библиотеки. Оно показывает, что прошлый repack сохраняет объявления интеграции и `.so`, но изменяет подпись и упаковку.
- **Извлечение каталога Android-ресурсов:** использовано для проверки каждого добавленного имени ресурса и плейсхолдеров форматирования; 488 ключей существуют в оригинальном каталоге.
- **Аудит исходников/CI:** показал, что предыдущая сборка модуля упала только на `ExpiredTargetSdkVersion` (`targetSdk 28`), тогда как проверка исходника и переводов завершилась успешно.
- **Скриншоты телефона:** показывают частичную локализацию и системный запрос запуска Mi Fitness на китайском. Этот запрос относится к системному переходу между приложениями и сам по себе не доказывает успех синхронизации.

Эти проверки согласуются по главному выводу: для минимального риска нужна локализация в отдельном модуле, ограниченном процессом исследования, а не пересборка APK Xiaomi. Полного инструментального теста авторизации/чтения/записи данных на физическом телефоне пока нет.

## 8. Build blocker runtime-модуля

В workflow `38121887672` исходный код прошёл source verification, но сборка остановилась на `:app:lintVitalRelease`: `targetSdk 28` вызвал `ExpiredTargetSdkVersion`. В следующем проектном патче `targetSdk` повышен до 35; это устраняет конкретно найденную причину отказа, но успешность следующей сборки подтверждается только новым журналом GitHub Actions.

В v3 добавлены/уточнены русские подписи элементов исследований сердца, артериального давления, сна, дневника сна, беговых рисков и подключения устройств. Для всех затронутых строк проверены имена ресурсов по каталогу, сохранение форматных плейсхолдеров и HTML-якорей.

Код runtime-hook не менялся: модуль по-прежнему активируется только для `com.mi.healthresearch`, заменяет строки ресурсов и делает exact-match замену текста `TextView`. Не перехватываются Intent, `DefaultRemoteService`, `JumpActivity`, Binder, PackageManager, URL/WebView или синхронизация. Сам Xiaomi APK, подпись, manifest, DEX и нативные библиотеки остаются byte-for-byte вне изменений.

Ограничение проверки: GitHub CI подтверждает сборку APK модуля и source-level проверки. Эмуляторный smoke test не запустился, так как раннеру недоступна системная библиотека `libpulse.so.0`; реальную связку с Mi Fitness, авторизацию, чтение/запись и все экраны необходимо подтвердить на телефоне. Диалог Android с предложением открыть Mi Fitness относится к системному UI и намеренно не переводится модулем.
