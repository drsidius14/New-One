# Метод патчинга

1. Проверить SHA-256 исходника по `config/project.json`.
2. Декомпилировать базу закреплённой версией Apktool.
3. Извлечь фактические Android-ресурсы и текстовые assets в каталог JSON/CSV.
4. Добавлять перевод только по существующему имени ресурса в `patches/ru/resources.json`.
5. Для HTML/JS и прочих текстовых файлов добавлять переопределение в `patches/ru/assets/overrides/<путь-относительно-assets>`.
6. Скрипт проверяет ключи, форматные плейсхолдеры (`%1$s`, `%d` и т.п.) и русские формы множественного числа, затем вносит overlay `values-ru`. Исходные DEX, нативные библиотеки и манифест патчером не редактируются.
7. Собрать, выровнять и подписать APK временным CI-ключом; проверить подпись.

## Важные нюансы

- Android-строки локализуются по ресурсным ключам, а не массовой заменой текста в APK.
- Значение с плейсхолдерами должно сохранять тот же набор плейсхолдеров, иначе возможны падение или некорректный вывод.
- Для русских `plurals` обязательно задать `one`, `few`, `many`, `other`.
- Часть текста может приходить из сервера, WebView, картинок, DEX или нативного кода. Такой текст не изменится этим ресурсным патчем; каталог текстовых assets помогает обнаружить одну из таких категорий.
- Ресурсный каталог создаётся workflow после первого push, а не придумывается заранее.
